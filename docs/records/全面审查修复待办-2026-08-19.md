- P0 R5 毛利率/费用率异常：成本、销售费用、管理费用、财务费用缺失时不再按 0 参与判定；当期成本和费用均缺失时返回 insufficient_data。
- P1 impact_advice 模板计数：模板兜底统计改用 all_segments，财务规则信号不再恒为 0。
- P1 comparison 单指标模板：两家公司数值相等时输出“接近”，不再误写“低于”。
- P1 events_impact_service LLM 客户端：直接创建的 provider 用完后关闭 AsyncOpenAI client。
- P1 Chroma 默认检索对象：默认 ChromaVectorStore 改为进程级惰性单例，避免每次请求重建。
- P1 Neo4j 查询超时：Neo4jEquityGraph 统一通过 `_execute_query()` 包装 Cypher，并使用 `neo4j.Query(timeout=30)` 应用 `_QUERY_TIMEOUT`。
- P1 WS 非对象输入：WebSocket 顶层 JSON 或 `payload` 非对象时返回可恢复错误，不再因 `.get()` 崩溃断开连接。
- P1 report 状态覆盖：后台报告启动/成功/失败更新增加期望前置状态条件，迟到任务不能覆盖重试后的状态。
- P1 财务 provenance 严重等级：财务 Claim 持久化使用规则真实 severity，不再统一写入 `medium`。
- P1 R1/R5/R7 期次一致性：R1、R5、R7 的跨字段判定按 report_period 对齐，解释文本使用实际 current_period。
- P1 source resolver Engine：研究报告来源解析复用公共 profile-key Engine，不再每次手工拼接连接串和创建连接池。
- P1 上市日期问法实体误切分：`康美药业什么时候上市的` 不再额外生成伪公司 mention `时候上市`。
- P1 同公司名称+代码重复主体：`康美药业 600518.SH 的公告` 在身份锁定后按 wind_code 合并，不再误入多公司关系澄清；显式比较同一公司的场景仍保留并返回 `comparison_missing_peer`。

## 后续待办

- P1 LLM 建议数字锁定：impact_advice/comparison 的 prompt 已要求不得新增数字，但校验层还没有统一抽取并比对“输出数字必须来自 locked facts”的机制。建议新增共享 numeric lock validator，覆盖 overall/suggestions/paragraphs。
- P1 evidence SELECT -> INSERT 并发竞态：需对 provenance/evidence 落库路径做唯一键冲突和幂等 upsert 全链路审计，并补并发单测。
- P1 report 状态回跳：需系统审计 `report_jobs` 状态机，只允许 queued -> running -> completed/failed 或 failed -> queued retry，避免后台慢任务覆盖新状态。
- P2 `/sessions` 正式鉴权策略：如进入多人部署，需要从 user_id 参数升级为认证主体注入，并补越权访问测试。
- P2 Chroma 单例生命周期：当前单例解决重复构造；后续可补显式关闭/健康恢复策略，用于长生命周期服务进程运维。
- P1 指标期次请求未严格执行：官方 observed 中，明确请求 `2025年`、`今年上半年`、`三季度变化`、`最近三年` 时，部分回答退化为最新可用单期（如 2026Q1），但没有明确提示期次不匹配。应在指标查询层锁定 requested period/policy；无匹配数据时返回 unsupported/insufficient_data，禁止静默换期。
- P1 报表口径冲突未显式拒绝：官方 observed 中用户请求“合并口径”，系统仍按项目固定母公司口径返回结果。固定母公司口径是产品铁律，但回答必须明确拒绝口径切换，不能只在尾部说明后继续给出容易被误读的数值。
- P1 跨公司 company_fact 联网补全不一致：单公司上市日期可通过 AnySearch 回填，但“中国石化的上市日期比中国石油早几年”仍报告双方日期不可用。需让 cross-company fact 与 single-company fact 复用同一受控回填和证据链。
- P2 实体填充词仍有漏网：官方 observed 中“英科医疗这段时间涨幅较大，请帮我简单分析”把“简单”识别为第二个疑似公司并阻断。应以候选/语义上下文消歧为主补回归，避免继续无限扩充停用词表。
- P2 写守卫显式 Engine 误告警：`SessionCleanupService(engine=truthnet_test_engine)` 仍按全局 settings 判断并打印演示库告警。当前守卫只 warning、不阻断，实际写入目标经 `SELECT DATABASE()` 验证为测试库；后续应允许守卫读取实际 Engine profile，避免误报或漏报。
- P2 官方 81 题目前全部为 `to_verify`：runner 的 `observation_count=81, errors=0` 只证明执行与契约无异常，不代表答案准确率。需完成 sidecar 人工标注为 `verified/supported` 后才能产出 scored_count 和准确率。
