## 执行顺序

```
依赖关系：
  后端 ① Finance Agent ← 数据 ① 规则函数 + ③ 行业分位
  后端 ② Events Skill  ← 数据 ④ 事件聚类 + ⑤ 评级拐点

第一步：数据 ①③④⑤ → 提交到仓库/写入 MySQL
    先交这 4 项，后端 ①② 才能开工
    （前端继续用 Mock，不等）

第二步：后端 ①② 拿到数据产物 → Finance Agent + Events Skill
    数据 ②⑥ 同时做造假手法库 + 造假验证

第三步：后端 ③-⑯ 交叉验证 + Claim/Evidence + 风险评分 + 记忆 Agent + REST 端点
    前端 ①-⑧ 切真实 API，与后端联调

联调节点：后端 ⑨-⑬（REST 端点）、⑭（画像/股权）、⑧（会话）完成即可开始前后端对接

全程并行：
  数据 ② 造假手法库（老师点名，不依赖其他任务，尽早启动）
  数据 ⑦ 评测框架（独立脚本，不依赖其他任务）
```

## 开发规范提醒

- 每个任务做完：git push 到个人分支 → 群里报进度
- 代码底线：UTF-8，API 路径 `/api/v1/...`，响应 `{data, meta, warnings}`
- commit 格式：`feat: / fix: / docs: / chore:`
- 提交前跑：doctor.py + ruff + pytest + pnpm build
