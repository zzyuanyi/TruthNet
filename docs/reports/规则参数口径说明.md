# 规则参数口径说明（会7 参数含义/当前值）

> **用途**：前端「会7 规则配置页」在画像页展示每条规则的参数和当前值。本文档是 R1–R7 规则参数的**口径说明**，可直接被会7 页面消费。
> **数据来源**：`backend/app/domain/finance/financial_rules.yaml`（version=1.1.0，运行时配置本体）
> **规格来源**：`docs/RULES_SPEC.md`（v1.0.2，公式/适用条件/严重等级映射）
> **字段覆盖率**：MySQL `truthnet_test` 实测（SQL 见附录 A）
> **生成日期**：2026-08-22 ｜ 数据组 B

## 0. 口径说明（必读）

1. **「当前值」权威来源**：本页所有「当前默认值」= `financial_rules.yaml` 运行时配置，由 `GET /api/v1/rules/definitions` 返回，会7 页按此展示。**不以 RULES_SPEC 为运行时依据**——RULES_SPEC（v1.0.2）是规格层（表述抽象，如 `gap > 20pp`），YAML（v1.1.0）是运行时落地（具体到每个参数 key 的数值）。两者语义一致、粒度不同，本文档同时呈现并在「理由」列标注规格出处。
2. **报表口径**：固定**母公司报表**（`statement_type=408006000`，`statement_scope=parent_company`），不读取合并报表（408001000）；字段缺母公司数据返回 `insufficient_data`，绝不回退合并口径。
3. **公司类型**：仅非金融企业（`comp_type_code=1`）；银行/保险/证券（2/3/4）→ `not_applicable`；NULL/非法 → `insufficient_data`。实测非金融企业 5,971 家（占 6,713 家的 89.0%，详见附录 A）。
4. **触发结果状态**：`triggered` / `not_triggered` / `not_applicable` / `insufficient_data`。**字段不足 → `insufficient_data`，不套用通用规则**——这正是本文档覆盖率数据要佐证的点。
5. **展示形态对齐**：参数名与 `financial_rules.yaml` / API 完全一致（参数 key 由前端按 key 匹配展示，不得改名）。**单位口径**：本文档表格用可读符号（`%` / `pp` / `ratio` / `quarters` / `days` / `CNY`），API 返回的 `unit` 字段为 `percent` / `pp` / `ratio` / `quarters` / `days` / `CNY`（`percent` 即 `%`），会7 页按 `parameters[].unit` **原样渲染**（百分比显示为 "percent" 而非 "%"，属预期）。两套符号等价，对应关系见各参数表。

### 0.2 严重等级定义

| 等级 | 定义 |
|---|---|
| red | 高风险，信号强且多期持续，建议重点关注 |
| orange | 中高风险，信号明确但程度或持续性不足 |
| yellow | 中等关注，单项指标偏离，需结合其他规则判断 |
| blue | 当前未触发，仅记录 |
| green | 指标健康 |

### 0.3 公共约定

- **增速计算**：统一同比增长率 `yoy(t) = (value(t)-value(t-4Q)) / |value(t-4Q)|`；分母为 0/NULL → `insufficient_data`；大额科目分母 < 1 万元做下限保护（`denominator_small`）。
- **利润表科目为累计值**（Q1=1-3月…Q4=1-12月），YoY 仅同一报告期之间比较；比值类指标分子分母同口径不受累计值影响；需要单季度值（如 R4 周转天数年化）必须先 `cumulative(t) - cumulative(t-1Q)` 还原。
- **行业分位**：按申万一级行业（`industry_l1`）分组，同行有效样本 ≥5 才计算；<5 → 仅用 absolute_threshold（`not_applicable` 行业分位）；分位用 `percentile_rank`（非插值）。

## 1. R1 · 应收–营收背离

| 项 | 值 |
|---|---|
| 规则说明 | 应收账款增速持续且显著高于营业收入增速，可能表明通过放宽信用政策、提前确认收入甚至虚构销售来粉饰营收（YAML metadata） |
| 输入字段 | `balance_sheet.acct_rcv`（应收账款期末余额）、`income_statement.oper_rev`（营业收入累计） |
| 核心公式 | `acct_rcv_yoy - oper_rev_yoy = gap`（gap 为背离幅度，单位 pp）；另算 `gap` 的行业分位 |
| 严重等级条件 | red：gap>50pp 且连续两期严重背离；或应收暴增但营收下滑。orange：gap>30pp 且应收增长；或连续两期中等背离。yellow：gap>20pp |
| 适用条件 | acct_rcv/oper_rev 近 4 期至少 3 期有值；非金融企业；近 2 期口径一致；\|acct_rcv(t-4Q)\|≥1 万元 |

**参数表**：

| 参数名 | 含义 | 当前默认值 | 单位 | 理由（依据） |
|---|---|---|---|---|
| yellow_gap_pp | 轻度背离阈值：应收增速超营收增速达到此值触发黄色 | 20 | pp | 应收增长与营收增长的合理偏离上限（RULES_SPEC §2.4 absolute_threshold）；偏离>20pp 即需关注收入确认节奏 |
| orange_gap_pp | 中等背离阈值（橙色） | 30 | pp | 背离扩大信号（§2.4 absolute_threshold_orange） |
| orange_consecutive_gap_pp | 连续两期背离的橙色判定阈值 | 20 | pp | 连续两期 gap>20pp 说明非偶发（§2.6 orange 场景 2） |
| orange_previous_gap_pp | 上一期背离阈值（与当期组合判连续） | 20 | pp | 配合当期判定"连续两期中等背离" |
| red_consecutive_gap_pp | 连续多期严重背离阈值（红色） | 50 | pp | 严重背离基准（§2.4 absolute_threshold_red） |
| red_previous_gap_pp | 上一期严重背离阈值（与当期组合判连续） | 30 | pp | 连续两期严重背离：当期>50pp 且上期>30pp（§2.6 red 场景 1） |
| red_declining_revenue_gap_pp | 营收下滑场景的背离阈值（红色） | 30 | pp | 应收暴增但营收下滑组合中的背离下限（§2.6 red 场景 2） |
| red_receivable_growth_pct | 应收暴增阈值（红色） | 50 | % | 应收同比增速>50% 视为暴增（§2.6 red 场景 2） |

**字段覆盖率**：acct_rcv **90.1%**，oper_rev **97.8%**（实测，SQL 见附录 A）——核心字段覆盖良好，R1 可广泛触发。

## 2. R2 · 现金流–利润背离

| 项 | 值 |
|---|---|
| 规则说明 | 净利润持续为正但经营现金流持续为负或远低于净利润，利润缺乏现金支撑（YAML metadata） |
| 输入字段 | `income_statement.net_profit_excl_min_int_inc`（净利润不含少数股东损益）、`cash_flow.net_cash_flows_oper_act`（经营活动现金流净额） |
| 核心公式 | `cf_to_profit_ratio = net_cash_flows_oper_act / \|net_profit_excl_min_int_inc\|`；`consec_neg_cf`=近 4 期盈利但现金为负的连续期数；`avg_cf_ratio`=近 4 期均值 |
| 严重等级条件 | red：盈利且现金为负连续≥3 期；或利润增长>20% 且现金流持续恶化（连续≥2 期）。orange：盈利且现金为负连续≥2 期；或盈利且 0≤现金/利润比<0.3。yellow：盈利且现金为负 1 期；或 0.3≤现金/利润比<0.5 |
| 适用条件 | 两字段非 NULL；非金融企业；报表期对齐；\|净利(t)\|≥1 万元；公司亏损且现金流出 → `not_applicable`（非粉饰信号） |

**参数表**：

| 参数名 | 含义 | 当前默认值 | 单位 | 理由（依据） |
|---|---|---|---|---|
| yellow_cashflow_profit_ratio | 现金/利润比黄色阈值 | 0.5 | ratio | 现金/利润比<0.5 即不足一半利润有现金支撑，需关注（§3.4/§3.6 yellow） |
| orange_cashflow_profit_ratio | 现金/利润比橙色阈值 | 0.3 | ratio | 现金/利润比<0.3 为明显背离（§3.4 absolute_threshold；§3.6 orange） |
| orange_consecutive_negative_cashflow_periods | 连续负现金流橙色阈值 | 2 | quarters | 连续≥2 期盈利但无现金（§3.6 orange 场景 1） |
| red_consecutive_negative_cashflow_periods | 连续负现金流红色阈值 | 3 | quarters | 近 4 期中 3 期盈利但无现金，信号强烈（§3.6 red 场景 1） |
| red_profit_yoy_pct | 利润增速红色阈值 | 20 | % | 利润增长>20% 但现金持续恶化，粉饰嫌疑大（§3.6 red 场景 2） |
| red_growth_consecutive_periods | 利润增长但现金恶化的连续期数（红色） | 2 | quarters | 连续≥2 期增长无现金支撑（§3.6 red 场景 2） |

**字段覆盖率**：net_profit_excl_min_int_inc **100.0%**，net_cash_flows_oper_act **99.9%**（实测）——字段充分，R2 可广泛触发。

## 3. R3 · 存贷双高

| 项 | 值 |
|---|---|
| 规则说明 | 同时持有大量货币资金与大量有息负债，可能意味着货币资金虚增、受限或被占用（康美模式）（YAML metadata） |
| 输入字段 | `balance_sheet.monetary_cap`（货币资金）、`st_borrow`（短期借款）、`lt_borrow`（长期借款）、`tot_assets`（资产总计）；`income_statement.less_fin_exp`（财务费用，辅助） |
| 核心公式 | `cash_to_assets = monetary_cap/tot_assets`；`debt_to_assets = (st_borrow+lt_borrow)/tot_assets`；`implied_interest_rate = less_fin_exp/有息负债`；`dual_high_flag = cash>15% AND debt>20%` |
| 严重等级条件 | red：双高且隐含利率>5%（现金可能不存在/受限）；或双高且持续扩大。orange：双高同时满足（现金>15% 且负债>20%）。yellow：现金占比>20% 且存在有息负债（未达双高） |
| 适用条件 | monetary_cap/st_borrow+lt_borrow/tot_assets 非 NULL；非金融企业；tot_assets>0；**可选字段 bonds_payable / non_cur_liab_due_within_1y 不在 V12 Schema 中 → 有息负债仅含 st_borrow+lt_borrow，债务口径偏保守** |

**参数表**：

| 参数名 | 含义 | 当前默认值 | 单位 | 理由（依据） |
|---|---|---|---|---|
| dual_high_cash_pct | 货币资金占比双高阈值 | 15 | % | 货币资金占总资产>15% 视为偏高（§4.4 absolute_threshold_cash）；双高判定基准 |
| dual_high_debt_pct | 有息负债占比双高阈值 | 20 | % | 有息负债占总资产>20% 视为偏高（§4.4 absolute_threshold_debt）；双高判定基准 |
| yellow_cash_pct | 现金占比黄色阈值 | 20 | % | 现金>20% 且存在有息负债即触发黄色（未达双高，§4.6 yellow 场景 2） |
| red_cash_pct | 现金占比红色阈值 | 25 | % | 极端双高：现金>25%（§4.4 absolute_threshold_extreme） |
| red_debt_pct | 负债占比红色阈值 | 25 | % | 极端双高：负债>25%（§4.4 absolute_threshold_extreme） |
| red_implied_interest_rate_pct | 隐含利率红色阈值 | 5 | % | 双高且借款成本>5% → 大量借款真实付息而现金存疑，现金可能不存在/受限（§4.6 red 场景 1） |

**字段覆盖率**：monetary_cap **98.8%**，tot_assets **100.0%**，st_borrow **60.0%**，lt_borrow **41.3%**（实测）——有息负债两字段覆盖中等偏低，**债务口径偏保守**（可选字段缺位 + st/lt_borrow 非空率 60%/41%），R3 的债务侧判断依赖这两字段。

## 4. R4 · 存货–营收背离

| 项 | 值 |
|---|---|
| 规则说明 | 存货增速持续显著高于营收增速，或存货周转天数大幅延长，可能存在产品滞销、存货积压乃至通过少结转营业成本虚增利润（YAML metadata） |
| 输入字段 | `balance_sheet.inventories`（存货）、`income_statement.oper_rev`（营业收入累计）、`less_oper_cost`（营业成本累计） |

## 5. R5 · 毛利率/费用率异常

| 项 | 值 |
|---|---|
| 规则说明 | 毛利率或费用率短期显著变化，且与自身历史趋势和行业方向不一致，可能存在成本少结转或费用资本化（YAML metadata） |
| 输入字段 | `income_statement.oper_rev`、`less_oper_cost`、`less_selling_dist_exp`（销售费用）、`less_gerl_admin_exp`（管理费用）、`less_fin_exp`（财务费用） |

| 严重等级条件 | red：毛利率偏离>15pp 且行业同向偏离>15pp 且逆行业趋势（opposite_direction）；或毛利率升>10pp 且费用率降>10pp（两端同时优化）。orange：毛利率偏离>10pp 且行业偏离>10pp；或费用率降>5pp 且费用率低于行业 P10。yellow：毛利率偏离>10pp；或费用率下降>5pp；或综合偏离>15pp |
| 会7 页展示文案（YAML conditions 原文，简化） | red：毛利率偏离>15pp（极端偏离）；或毛利率升且费用率大幅降（异常叠加）。orange：毛利率偏离>10pp；或费用率下降>5pp。yellow：毛利率偏离>10pp；或费用率下降>5pp；或综合偏离>15pp |
| 适用条件 | oper_rev 近 8 期至少 6 期有值；less_oper_cost 非 NULL；销售/管理费用至少一个非 NULL；非金融企业；oper_rev(t)>0；历史数据<4 期仅用行业对比置信度降一级 |

**参数表**：

| 参数名 | 含义 | 当前默认值 | 单位 | 理由（依据） |
|---|---|---|---|---|
| gross_margin_deviation_pct | 毛利率偏离自身均值阈值 | 10 | pp | 毛利率偏离 8 季均值>10pp 触发（§6.4 absolute_threshold_gm） |

| red_expense_rate_drop_pct | 费用率下降红色阈值 | 10 | pp | 毛利率升同时费用率降>10pp，异常信号叠加（§6.6 red 场景 2） |

**字段覆盖率**：oper_rev **97.8%**，less_oper_cost **94.0%**，less_selling_dist_exp **84.0%**，less_gerl_admin_exp **100.0%**，less_fin_exp **97.7%**（实测）——字段充分，R5 可广泛触发。

## 6. R6 · 其他应收款与关联占用风险

| 项 | 值 |
|---|---|
| 规则说明 | 其他应收款异常增长且占比偏高，可能是关联方资金占用、虚假交易的"垃圾桶"科目（YAML metadata） |
| 输入字段 | `balance_sheet.oth_rcv`（其他应收款）、`tot_assets`、`acct_rcv`（应收账款，用于对比）；图谱关联方关系（Phase C 接入） |
| 核心公式 | `oth_rcv_to_assets = oth_rcv/tot_assets`；`oth_rcv_to_acct_rcv = oth_rcv/acct_rcv`；`oth_rcv_yoy` 同比增速；`oth_rcv_large = oth_rcv > 5000万元` |

## 7. R7 · 盈利质量与非经常性依赖

| 项 | 值 |
|---|---|
| 规则说明 | 净利润增长应来自主业改善；若显著高于扣非利润、经营现金流和营收增长，可能存在依赖一次性收益粉饰（YAML metadata） |
| 输入字段 | `income_statement.net_profit_excl_min_int_inc`、`net_profit_after_ded_nr_lp`（扣除非经常性损益后净利润）、`oper_rev`、`oper_profit`（营业利润）、`tot_profit`（利润总额）；`cash_flow.net_cash_flows_oper_act` |
| 核心公式 | `core_profit_ratio = 扣非净利/净利`；`non_recurring_ratio = 非经常性/净利`；`quality_divergence = 净利增速-扣非增速`；`revenue_divergence = 净利增速-营收增速`；`cash_divergence = 净利增速-现金流增速`；`non_operating_ratio = (tot_profit-oper_profit)/\|tot_profit\|` |
| 严重等级条件 | red：扣非占比<0.3 且质量/营收严重背离；或扣非占比<0.5 且连续依赖+现金流不支撑。orange：扣非占比<0.5 且质量/营收背离；或扣非占比<0.3（极依赖非经常性）；或营业外占比>50%。yellow：扣非占比<0.5；或质量/营收背离；或营业外占比>30% |
| 适用条件 | 净利/扣非字段非 NULL；非金融企业；\|净利(t)\|≥1 万元；净利>0（盈利时判断盈利质量）；**扣非字段不可用 → 简化为 revenue_divergence + cash_divergence，名称改"盈利质量（简化版）"，置信度降一级，等级上限 orange** |

**参数表**：

| 参数名 | 含义 | 当前默认值 | 单位 | 理由（依据） |
|---|---|---|---|---|
| weak_core_profit_ratio | 扣非占比较弱阈值 | 0.5 | ratio | 扣非/净利<0.5 说明过半利润来自非经常性（§8.4 absolute_threshold_core_ratio），黄色基础场景 |
| red_core_profit_ratio | 扣非占比红色阈值 | 0.3 | ratio | 扣非/净利<0.3 说明超 7 成利润来自非经常性（§8.4 absolute_threshold_core_ratio_severe），极依赖非经常性 |
| quality_divergence_pp | 扣非背离阈值 | 30 | pp | 净利润增速远超扣非利润增速>30pp（§8.4 absolute_threshold_quality_div） |
| revenue_divergence_pp | 营收背离阈值 | 20 | pp | 净利润增速远超营收增速>20pp（§8.4 absolute_threshold_revenue_div） |
| cash_divergence_pp | 现金流背离阈值 | 30 | pp | 净利润增速远超经营现金流增速>30pp（§8.4 absolute_threshold_cash_div） |
| yellow_non_operating_ratio_pct | 营业外占比黄色阈值 | 30 | % | 营业外收支占比>30% 判黄（§8.4 absolute_threshold_non_operating；§8.6 yellow） |
| orange_non_operating_ratio_pct | 营业外占比橙色阈值 | 50 | % | 营业外收支占比>50% 判橙（§8.6 orange 场景 4） |

**字段覆盖率**：net_profit_excl_min_int_inc **100.0%**，net_profit_after_ded_nr_lp **0.0%**，oper_rev **97.8%**，oper_profit **100.0%**，tot_profit **100.0%**，net_cash_flows_oper_act **99.9%**（实测）

> ⚠️ **关键口径（重要）**：**扣非净利润字段 `net_profit_after_ded_nr_lp` 覆盖率为 0.0%**（全部 NULL）。因此 R7 **当前实际以"盈利质量（简化版）"运行**——仅用 revenue_divergence + cash_divergence 判断，严重等级上限为 **orange**（不会触发 red），`weak_core_profit_ratio`/`red_core_profit_ratio` 两参数因扣非字段缺失**无法参与计算**（按 RULES_SPEC §8.5 降级处理）。此口径与任务1报告 §5.4「net_profit_after_ded_nr_lp 覆盖率 0%」一致。

## 附录 C：给前端会7 页的使用说明

1. 会7 页消费 `GET /api/v1/rules/definitions`（返回 `thresholds` + `metadata.parameters[]`），展示形态为「参数 key（描述）→ 当前值 单位」，与本文档各规则参数表一致。
2. 前端按 `parameters[].key` 匹配展示，**不要自行改名**；`unit` 直接取 metadata 提供值并按原值渲染（`percent` 即 `%`，页面显示 "percent" 属预期，无需转换）。
3. 严重等级条件（red/orange/yellow）从 metadata `conditions` 取，会7 页按此展示。本文档「严重等级条件」行以 YAML conditions 原文为主，个别规则按 RULES_SPEC 补注完整数值/场景（R4 red 括号数值、R7 red 第 2 场景分别来自 §5.6 / §8.6）；**R5 例外**——其 conditions 为简化展示文案，表内已额外附「RULES_SPEC §6.6 完整判定逻辑」行。
4. 若需展示"字段不足→insufficient_data"提示，可用附录 A 覆盖率数据向用户说明规则可能因字段缺失而降级（尤其 R3 债务侧、R7 扣非侧）。
