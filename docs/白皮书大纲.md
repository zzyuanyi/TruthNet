## 三、六项核心创新

### 创新1：银行/保险/证券差异化反欺诈规则

**问题**：
通用反欺诈规则对金融企业不适用。以「存贷双高」（R3）为例：对普通企业而言，货币资金与有息负债同时处于高位是资金被占用或虚增的警示信号；但对银行，存贷款本就是主营业务，直接套用通用规则会大量误报。因此必须为银行、保险、证券三类金融企业建立专属规则，不能一刀切排除。

**实现（数据基础）**：
1. MySQL 全量入库：公司 + 三表（资产负债表/利润表/现金流量表）+ 股东 + 公告 + 研报，共 7 张表、约 83 万行
2. 公司类型识别：`comp_type_code` 标注完成（1=非金融 5,973 家 / 2=银行 48 家 / 3=保险 5 家 / 4=证券 45 家）
3. 行业分类补全：申万一级行业覆盖率 99.2%（6,428/6,481）
4. 金融企业专属字段导入 41 个，覆盖三类：
   - 银行：`loans_and_adv_granted`（发放贷款）覆盖率 93.6%、`net_int_inc`（利息净收入）99.6%
   - 证券：`clients_cap_deposit`（客户资金）95.6%、`net_handling_chrg_comm_inc`（手续费净收入）96.5%
   - 保险：`prem_inc`（保费）等字段样本严重不足（仅 1 条），标记 `insufficient_data`，不套用通用规则

**证据**：
- [数据] comp_type_code 分布：非金融 5,973 / 银行 48 / 保险 5 / 证券 45
- [数据] 金融专属字段覆盖率表（见 `docs/FINANCE_FIELDS_MAPPING.md`）
- [截图] MySQL 各表 `SELECT COUNT(*)` 结果

**结果**：
- 银行/证券各有 ≥2 个覆盖率 90%+ 的专属字段可用，可支撑差异化规则
- 保险字段样本不足，明确走 `insufficient_data` 路径（不伪造、不套用）
- 金融企业被准确识别与区分，为后端 #11 差异化规则提供前置数据

### 创新6：相似历史案例检索

**问题**：
用户看到某公司触发了风险信号（如「应收–营收背离」）后，最自然的追问是「以前有没有别的公司也出现过同样的情况、后来怎么样了」。传统工具只给出当前公司的分数，无法回答「历史参照」。

**实现（数据基础）**：
1. ChromaDB 向量库：入库研报摘要 55,214 篇，分块 147,492 个，BGE-small-zh-v1.5 中文嵌入
2. 相似案例检索 Provider（`backend/app/application/services/similar_case_provider.py`，`RealSimilarCaseProvider`，PR #42 已合入 main）：按触发规则的核心指标（R1→gap、R3→存贷双高、R5→毛利率等），在同行业内检索指标值最接近的公司
3. 指标口径与规则引擎完全一致（母公司报表 408006000、非金融企业），保证「检索到的参照」和「触发信号」用的是同一把尺子
4. 排序：同行业优先，IQR 标准化距离（抗离群值）

**证据**：
- [数据] ChromaDB collection `research_report_chunks`：147,492 文档
- [数据] 检索验证：康美药业 R1（gap=13.2pp）→ 返回中科美菱（gap=13.32）、珈凯生物（14.38）等同行业公司
- [截图] 相似案例检索运行结果（数据组原型 `scripts/similar_cases.py R1 600518.SH`；正式实现为 `RealSimilarCaseProvider`）

**结果**：
- 覆盖 A 股非金融企业，7 条规则各有核心指标可检索
- 样本充足返回 Top 5 相似案例（含公司/时期/指标值/证据来源）；样本不足明确返回「暂无相似案例」
- 相似性只表述为「指标值相近」，绝不表述为「同类造假」（合规底线）
